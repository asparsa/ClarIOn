ClarIOn vs Chimbuko anomaly detection · precision / recall / scalability
What this is

A controlled comparison of ClarIOn's call-tree anomaly detector against Chimbuko's two primary detection algorithms, on identical synthetic traces with known ground truth.

ClarIOn runs as its real clarion_calltree --detect-anomaly binary. Chimbuko is represented by faithful offline reimplementations of its documented algorithms: SSTD (per-function mean ± ασ) and HBOS (per-function histogram-density score). Each injected operation is a leaf occurrence repeated 60 times under its own root, so the per-occurrence samples ClarIOn aggregates are byte-identical to what the Chimbuko scorers see. The evaluation unit is per function: flagged or not. Figures are means over 5 seeds × 100 functions, 30% of them anomalous.

Mean F1 across the four anomaly families, at each tool's default setting (ClarIOn 50% band, SSTD 6σ, HBOS top-1%). The second line is the best F1 each tool can reach when its threshold is tuned per family.

Precision – recall curves

Each curve sweeps one tool's threshold. Up and to the right is better. ● marks the default setting, ■ the F1-optimal point. Hover any marker for exact values.

False positives under noise

The negative-control workload injects no anomalies — every flag is a false positive. Bars show the share of clean functions wrongly flagged at each tool's default setting.

Operating points

Precision (P), recall (R), F1, and false-positive rate (FP) for every family. Recall is undefined for the negative control (no positives); FP is the relevant metric there.

Scalability

Detection time versus trace size. ClarIOn is the C++ binary's detect-minus-aggregate wall-clock delta; SSTD and HBOS are the reference Python scorers. Absolute times are not comparable across a compiled binary and a Python prototype — read the slopes: every method is linear in event count (slope ≈ 1 on log-log axes).

How to read this, and what it does not cover
  • Scope. The workloads are per-function execution-time anomalies — the class both tools target. ClarIOn's subtree-shape "system" anomalies have no Chimbuko equivalent and are out of scope here.
  • Offline algorithms, not the live system. This compares detection logic on static traces. It does not exercise Chimbuko's real distributed runtime (ADIOS2 streaming, the parameter server's global model sync, the provenance database).
  • Why SSTD collapses on multi-outlier and subtle-shift. Its mean and σ are built from all occurrences including the anomalies, so a cluster of outliers inflates the baseline until the outliers sit inside the 6σ band. ClarIOn's median barely moves, so its percentage band stays anchored.
  • Why HBOS over-flags. As a univariate per-function histogram with a global score cutoff, a lone-sample tail bin in a normal function scores like a real spike, so precision stays low. HBOS is built for high-dimensional feature outliers, not single-series durations.
  • Time basis. ClarIOn compares inclusive duration; Chimbuko defaults to exclusive. The leaf occurrences here make the two identical, removing that variable.
